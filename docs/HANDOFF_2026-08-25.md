## 0. One paragraph

JobFit is a Chrome MV3 extension that annotates job postings on six job boards and can
generate a full "match report" rendered by the web app. It spans **three repos**
(`jobfit-extension`, `jobfit-backend`, `jobfit-frontend`) plus a Python AI service
(`jobfits-ai-service`). The 2026-08-25 session added multi-site support (CamHR + JobNet),
Khmer-language handling, "stated requirements" flags, advertised-salary display, and a
report cache version. **Four tasks remain** — see §6, in priority order.

`linkedin · indeed · khmer24 · bongthom · jobnet · camhr`

  one whose body never mentions experience, so 0 cannot be told from a blank field.
- Khmer digits (`០-៩` = U+17E0–17E9) and `ឆ្នាំ` ("years") are now read, **with age and

### 3.4 Advertised salary — DISPLAYED, never scored

3. **Line 9** says `_Last updated: 2026-08-13_`. Bump it.

**Acceptance:** nothing in `docs/PROGRESS.md` contradicts `PRIVACY.md`, `STORE_LISTING.md`
or `MULTI_SITE_PLAN.md`.

### 6.2 — §5 Save Job can silently erase a bookmark

`saved_external_jobs` upserts on `(userId, source, externalId)` and overwrites every field.
No capture timestamp, no content hash, no "save as new version". If an employer reuses a
job id, or an adapter grabs the wrong text, the user's original saved copy is gone with no
way to prove what it was.

**Suggested shape** (from the review): add `capturedAt` and a `contentHash` of the saved
description, keep `updatedAt`; offer "update saved copy" vs "save as new version"; warn
when the source content changed since capture; enforce the size cap client-side too.

**Files:** `jobfit-backend` — `prisma/schema.prisma` (+ migration, see trap #2),
`saved-external-job.repository.ts`, `saved-external-job.service.ts`,
`dto/save-external-job.dto.ts`. `jobfit-extension` — `src/content/SaveJobPanel.tsx`.

### 6.3 — Résumé ATS score is unstable (user-visible; user has APPROVED this fix)

**Measured 2026-08-25:** the same résumé (identical id `0d7b711c-…`) scored **ATS 85** at
08:12 and **ATS 95** at 08:37. Every sub-score moved (keywords 90→80, formatting 80→85).
The CV did not change — `qwen3:0.6b` answers differently each run.

Two consequences:
1. The advice contradicts itself between scans (±10 points is larger than most real CV
   improvements, so a user cannot measure progress).
2. `ResumeScorerService` **writes the score back onto `Resume.atsScore`**, so scanning any
   job silently changes the score shown on the user's résumé page in the web app.

The scorer already persists the score (`resume-scorer.service.ts`, ~line 107) but **never
reads it back** — it recomputes every time. Its own header comment says the values "are
cached back onto Resume.atsScore/qualityScore"; the cache is written and never used.

**Fix:** score a résumé once, reuse until the CV actually changes.

**Careful:** the scorer sets `resume.updatedAt = new Date()`, and
`MatchReportService.inputsChangedAt()` uses `resume.updatedAt` as the report cache's
freshness bar. Today this works only because scoring happens *before* the report row is
written. Do not break that ordering, and re-run the dedupe spec after changing it.

The user approved this but asked for it to be handed off rather than done in that session,
because it touches the web app's résumé page as well as the report.

### 6.4 — Advertised salary cannot be scored yet (BLOCKED — ask the user first)

`job.salary` is displayed (e.g. "USD 700 / month") but excluded from `subScores.salary`.

**Why:** `Profile.minSalary/maxSalary` are bare integers **with no period column**, and
this repo's own schema note records exactly why that matters — a Cambodian monthly figure
and a US annual one are indistinguishable in one column, and ~83% of the corpus is
Cambodian where monthly is the norm. Scoring `$700/month` against an unlabelled `60000`
means inventing the candidate's unit, possibly by a factor of 12.

**To unblock:** add `salaryPeriod` to `Profile` (schema + the profile form at
`jobfit-frontend/src/features/user-profile/components/career-preferences-form.tsx`), then
normalise both sides before comparing. **Ask the user before doing this** — it changes what
a sub-score means. The user already said "yes" to using the salary; the period column is
the part they have not decided on.

## 7. Traps — do not re-derive these the hard way

1. **The AI service must be reached at `127.0.0.1`, not `localhost`.** On Windows
   `localhost` resolves to IPv6 first and hits an unrelated container on `:8000`.
2. **`prisma migrate dev` is broken here.** The shadow-database replay fails on a
   pre-existing migration (`20260809090000_offer_messages` → "table `offers` does not
   exist"). Use instead:
   ```bash
   npx prisma db execute --file prisma/migrations/<name>/migration.sql --schema prisma/schema.prisma
   npx prisma migrate resolve --applied <name>
   npx prisma generate
   ```
3. **Adding a host to `content_scripts.matches` needs BOTH an extension reload and a tab
   reload.** Chrome never injects into tabs that were already open. A whole debugging round
   was lost to this.
4. **The backend runs `whitelist + forbidNonWhitelisted`.** One undeclared field rejects the
   WHOLE request. `POST /match-report` was silently 400-ing on every site because the
   extension sent `extraction` and the DTO didn't declare it. The DTO and the
   `CREATE_MATCH_REPORT` message are one contract in two repos — change them together.
5. **Real adverts state requirements as bare bullets**, not sentences containing the word
   "required" — the "Requirements:" heading carries that meaning and is not part of the
   bullet. A rule demanding a requirement word found *nothing* on a real DHL posting.
6. **In Khmer ads, a number next to `ឆ្នាំ` is usually an AGE, not experience.** A live ad
   reads `អាយុ18 ដល់ 30ឆ្នាំ` ("age 18 to 30 years") followed by `មិនទាមទារបទពិសោធន៍`
   ("does NOT require experience"). Without the age and negation guards, the report claimed
   the job wanted 30 years of experience.
7. **Never emit a score for something that was not measured.** A "neutral" cosine of 0.5
   equalled the remap ceiling, so an unmeasured skills score became 100 and unrelated jobs
   scored 89–95%. `overall` is now **null** when the skills comparison did not run.
8. **The content script's Tailwind is px-based, not rem** (`tailwind.content.config.ts`).
   `rem` resolves against the *host page's* root font-size, so a job board could shrink the
   whole UI. Do not "restore" rem.
9. **Overlays render into a body-level shadow host** (`src/content/OverlayLayer.tsx`),
   because the badge mounts inside the page's own job card and Khmer24's card clips
   overflow. Do not move panels back inside the badge.
10. **`qwen3:0.6b` is the weak link in everything AI.** It parses Khmer CVs badly, invents
    skills, copies its own prompt examples into answers, and scores the same CV differently
    each run. Before blaming pipeline code, check whether the model is the cause. `.env`
    notes switching to full `qwen3` on the GPU box.

```bash

const {PrismaClient}=require('@prisma/client');const p=new PrismaClient();
p.matchReport.findFirst({orderBy:{createdAt:'desc'}})
 .then(r=>console.log(JSON.stringify(r.payload,null,1).slice(0,3000)))
 .finally(()=>p.\$disconnect());"
```

Check a live job page's structured data before writing an adapter:

```bash
curl -s -A "Mozilla/5.0" -L "<job url>" | grep -o '"@type":"[A-Za-z]*"' | sort | uniq -c
```

`node_modules`):

```bash

cd ../jobfit-frontend && node -e "
const {JSDOM}=require('jsdom');const fs=require('fs');
const {pickAdapter}=require('/tmp/sites.cjs');
global.document=new JSDOM(fs.readFileSync('/tmp/page.html','utf8')).window.document;
```
