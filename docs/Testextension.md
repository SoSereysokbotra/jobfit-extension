===================ANALYSIS (Claude, 2026-08-10)=======================

## Verdict
- ✅ Extension works END-TO-END on localhost — every feature loaded, no errors.
- ✅ AI service confirmed working: `semantic=true` on all match calls (the résumé +
  profile embedding are being used, not the neutral fallback).
- ⚠️ The MATCH SCORES are the weak point — compressed and not discriminative.

## Sub-score reading (across the 5 jobs)
| Sub-score | Behaviour | Verdict |
|---|---|---|
| **Skills 32–37%** | Real semantic, but LOW even for software roles (SWE job only hit 43% in a controlled test) | ⚠️ under-discriminating |
| **Experience 80%** | Identical for ALL 5 jobs | ⚠️ constant — external jobs carry no experience requirement, so it doesn't vary |
| **Location 80% (Cambodia) / 40% (APJ)** | Differentiates by your location | ✅ working correctly |
| **Salary 50%** | Constant | ℹ️ neutral — these companies aren't in our DB, so no salary band to compare |
| **Industry 50%** | Constant | ℹ️ neutral — same reason |

**Net:** every job lands ~50–62%, so the number doesn't help you tell a good fit from
a bad one. The overall is dominated by the constant 80/50/50 sub-scores; the one
signal that *should* separate jobs — skills — is compressed into a narrow 32–43% band.

## Why (root causes, not extension bugs)
1. **Title-only matching (by design/TOS).** We never scrape the job description, so the
   job embedding is built from just "<title> at <company> <location>" — a very short
   string → weak semantic signal → cosine similarities cluster in a low, narrow range.
2. **Profile strength.** The résumé parsed as "Second-Year Student"; a thin profile makes
   a thin embedding. Completing **Profile Setup** (skills/experience/desired salary+industry)
   would sharpen both the embedding and the salary/industry sub-scores.
3. **Companies not in our DB.** Salary + industry + company sidebar need the company in the
   `companies`/`jobs` tables. LinkedIn SMEs (Digmarit, Quik Hire, etc.) aren't there → neutral.

## Specific issues to fix / check
- [ ] **"No skill gaps for this role 🎉"** is misleading. Real reason: no *similar* roles in
      our (tech-heavy) DB to compare a customer-service/marketing title against. Reword to
      distinguish "you're covered" from "no comparable roles to analyse".
- [ ] **Job 4 (Marketing Assistant)** result is truncated — the Skill-gaps and Salary lines
      have no text (other jobs show the empty-state message). Was it still loading, or did it
      render blank? Re-check.
- [ ] **Cover letter / Interview prep** were not exercised — only the buttons show. Click both
      and confirm real output (AI when up, template/static fallback otherwise).

## Recommendations (priority order)
1. **Complete Profile Setup** → richer embedding → higher, more separated skills scores.
2. **Re-test with a software job you'd actually fit** (e.g. "Junior Frontend Developer") to
   see whether skills climbs meaningfully — the truest test of match quality.
3. (Backend, optional) **Calibrate the skills scorer** to spread compressed cosine values —
   but this changes the web app's matching too, so evaluate before shipping.
